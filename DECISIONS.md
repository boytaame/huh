# Decisions & assumptions

- **Scaffold:** created Next.js manually instead of `create-next-app` because the workspace was not empty (`spec.md`). Pinned TypeScript 5.9 rather than the brand-new TS 7 for ecosystem safety.
- **First question:** originally §5.2's instant path (auto-sent default question). Addendum P3 replaces it: the thread opens in a composing state with chips and a focused input, and the default question is only sent if the user submits an empty input (stored with `hidden: true`). See the addendum section below.
- **Persistence:** uses tldraw's `persistenceKey="ai-canvas-v1"` as instructed. In tldraw 5 this persists to browser-local IndexedDB under that key (older versions used localStorage). It is still purely local, with no database/auth.
- **Instant anchoring:** the region, thread and arrow are created before the PNG capture and network call. The blob shows "Looking at your selection…" while the crop is encoded, then streams. This keeps selection → blob feeling immediate.
- **Image capture:** `editor.toImage(shapesInSelection, { bounds, format: 'png', background: true, padding: 0, pixelRatio: 2 })`, then downscaled client-side to at most 1600px on the long side. The yellow selection shape and arrows are excluded from the capture. A visible background is kept so dark text is legible to the vision model.
- **Crop reuse:** the PNG is cached on both the `ask-region` (`imageDataUrl`) and the `ai-blob` (`regionImage`), as specified, and re-sent on every follow-up.
- **HTML shapes in captures:** tldraw's raster export skips HTML custom shapes. `AiBlobShapeUtil.toSvg` therefore renders a plain-text approximation (last few messages) so a child selection over an AI answer still contains text. The real parent thread messages are also sent in `ancestorContext`, so the model is not relying on the approximation alone.
- **Context budget:** `buildContext` uses a character budget (default 12,000 chars ≈ 3k tokens) rather than counting tokens. Board summary is capped at 2,000 chars, ancestor context at 3,000, and thread history is trimmed oldest-first. Full board JSON is never sent.
- **Ancestor chain:** walks up to 3 levels via `parentId`. AI parents contribute their last 3 messages; text materials contribute up to 1,200 chars; image materials are described by type/size. Regions terminate the walk.
- **Parent detection:** the Ask tool picks the topmost non-arrow/non-region shape whose bounds overlap at least 40% of the drawn selection. This lets a blob be a parent (child threads) without picking up previous yellow overlays.
- **Placement:** tries right of the selection (80px gap), then below-right, below, left. Chooses the first collision-free candidate that is mostly visible in the viewport, falling back to the least-bad candidate. Arrow endpoints are bound to the region's right edge and the blob's left edge with `isPrecise: true`.
- **Streaming ownership:** streaming lives in `lib/stream.ts`, not in the React component, so panning/culling a shape does not abort the request. Store updates are throttled to ~55ms, and a stream is abandoned if its blob is deleted.
- **Retry:** the last request payload is retained per blob. Retry drops the failed assistant placeholder and re-sends the same payload, so history is not duplicated.
- **Export scope:** nodes include `image`, `text`, `ask-region` and `ai-blob` shapes only, matching the schema in §5.5. Other tldraw shapes (geo, draw, note, frames) are not exported. Edges come from native arrow bindings (start → end); parent links live in each node's `parentId`.
- **`getBoardContext()`** returns the board JSON and is exposed on `window` for debugging; prompts use the much smaller `buildContext` output instead.
- **UI chrome:** tldraw's default main menu and page menu are hidden (single-page board, no accounts). The title and Ask controls are custom overlays; exports live in tldraw's native top-right `SharePanel` slot so they never collide with the style panel.
- **Provider defaults:** Gemini 2.5 Flash, Claude Haiku 4.5, GPT-4o mini. All are overridable via `LLM_MODEL`; provider code is confined to `lib/llm.ts`.
- **No extra features:** no auth, DB, sync, OCR, PDF import, study modes, mobile tuning or billing, per §6.

## Addendum 1 (P1–P6)

- **P1 · input isolation:** done with React handlers on the blob's own DOM (`onPointerDown`, `onKeyDown`, `onContextMenu`, `onPaste`) plus native `wheel` listeners on the body and footer. React's synthetic events are not enough for the wheel: tldraw binds `wheel` natively on the canvas element, so a synthetic `stopPropagation` arrives after the camera already moved. The body's `user-select: text` is applied as an inline style (tldraw's cascade otherwise wins) so answer text can be selected and copied while the header keeps `cursor: grab` for dragging.
- **P1 · header drag:** the header deliberately does *not* stop pointer events, so tldraw's own move handles the drag; every other region of the card stops them. Wheel over the body scrolls the answer and only bubbles to the canvas at the scroll limit with Ctrl/Meta held (pinch-zoom escape hatch).
- **P2 · gap-first prompt:** the system prompt in `lib/llm.ts` asks for the specific missing step first (never a generic summary) and separates a short visible answer from optional detail with the `---MORE---` marker. `lib/answer.ts` splits on the marker: everything after it is the collapsed detail behind `More ▾` (`moreOpen`), and only the first line of the visible answer is shown when the thread is collapsed.
- **P2 · default question bubble:** the auto-sent first question is stored as a user message with `hidden: true`, so it never renders as an "Explain this part…" bubble; it still travels in history/export. Typing over it is unnecessary — the thread starts composing instead (P3).
- **P3 · composing state:** dragging a selection no longer calls the LLM. The blob is created with `status: "composing"`, five quick chips from `lib/chips.ts`, an autofocused textarea and no messages. Enter (or a chip) submits; Shift+Enter inserts a newline; Esc cancels. Submitting an empty input sends `DEFAULT_QUESTION` with `hidden: true`.
- **P3 · cancel semantics:** cancelling deletes the thread exactly like the trash button (region → arrow → blob cascade), with no confirmation dialog. It calls `editor.markHistoryStoppingPoint` first: the creation and the cancel often share one pending history diff, and without a stopping point the two diffs cancel out and `Ctrl+Z` cannot restore the thread. Verified: Esc → all three shapes gone → one undo restores region, arrow and blob in `composing`.
- **P4 · anchored regions:** `AskRegionProps` gained `anchorId` and `rel` (anchor-relative bounds). `lib/anchoring.ts` syncs regions whenever the anchor material moves/resizes, including manual region resizes (so `canResize` is on for regions), and skips the update when the region already matches its anchor-relative target — an `applying` flag alone was not reliable because tldraw store side effects can fire after the caller's guard clears.
- **P4 · blob offset:** `AiBlobProps.offsetFromRegion` stores the blob position relative to its region, so a manually dragged blob keeps that offset when the selection moves. `lib/placement.ts` still picks collision-free, viewport-clamped spots for new threads.
- **P4 · migrations:** both custom shape utils ship a versioned migration (`com.tldraw.shape.ask-region/1`, `com.tldraw.shape.ai-blob/1`) — tldraw rejects migration ids that do not use that prefix.
- **P5 · delete cascade:** `lib/lifecycle.ts` handles the three rules with no dialogs: blob → region + arrow, region → arrow (the blob survives as `detached` with a thumbnail of its selection), arrow → the blob is unlinked and detached. Child blobs survive as detached threads (`parentId` cleared). Each cascade is one undo step.
- **P5 · arrow `meta` link:** the region↔blob link lives in the arrow's `meta.thread` instead of only in bindings because tldraw removes arrow bindings *before* a shape's `beforeDelete` runs — binding lookups during the handler returned nothing.
- **P6 · polish:** blob width is fixed at 400px (spec range 380–420) with ≥14px body text; the header (title, collapse, trash) stays visible when collapsed, and collapsing leaves the header plus the first line of the answer. Thread accents come from a five-colour palette (`lib/threads.ts`) chosen per drag, and a detached blob keeps its colour (`AiBlobProps.color` — an extra prop beyond the spec's summary).
- **Not built:** the optional "Auto-explain on select" setting. The addendum marks it optional and the composing flow already gives explicit control.

## Addendum 2 (sessions A and C)

- **Wheel ownership (3.1):** the card attaches one native, non-passive `wheel` listener at its root. Ctrl/Cmd+wheel is preventDefault-ed so the browser page never zooms, then the board zooms around the pointer (`editor.zoomIn/zoomOut` with a viewport-space `Vec`) — superseding addendum-1's "let pinch through" note. Plain wheel only stops propagation, so the answer scrolls and the board neither pans nor zooms.
- **Send guards (3.2):** the send button is disabled when `draft.trim()` is empty or the blob is streaming, and `submit()` bails out early while streaming. Empty Enter is deliberately asymmetric: it sends the default question only while composing (no messages yet), and does nothing on a follow-up thread.
- **Selectable text (3.3):** the body keeps inline `user-select: text` / `cursor: text` and stops pointer events, so a drag selects text instead of moving the card. Only the header drags. Stopping propagation is not enough on its own: a browser text-selection drag still fires `dragstart`, which used to drag the answer out of the card instead of moving the thread. The card now cancels `dragstart` in a native capture listener (`preventDefault` + `stopPropagation`), sets `draggable={false}` on the body and `-webkit-user-drag: none` in CSS.
- **Stuck `streaming` after undo:** deleting a thread mid-request and undoing restored `status: "streaming"` with no request behind it, leaving the card on "Thinking…" with a disabled input forever. `lib/stream.ts` now exposes `hasActiveStream`, and `AiBlob` heals a restored blob (drops the empty assistant placeholder, returns to `idle`) only when no request is writing. A live stream is never touched — the check runs on every status/messages change, so it is a no-op while a request is in flight.
- **Prompt voice (3.5):** added the "stop after the last explanatory step" rule, and the per-chip instruction suffixes now live in `lib/chips.ts` (analogy, reason-only, one worked example with real numbers, verdict-first).
- **No length caps:** the 400-token cap and the "max ~80 words" prompt rule from addendum-2 are gone — they cut explanations off mid-step. Gemini and OpenAI are now called with no output-token limit at all; Anthropic keeps `max_tokens: 8192` only because its API requires the field, set far above any real answer. Length is now guided purely by the content rules (gap first, short steps), not by a budget.
- **Light-only board:** tldraw persists the user's colour scheme per browser (`TLDRAW_USER_DATA_v3`), so a stored `dark`/`system` scheme painted the canvas `#101011` behind this app's white title bar, Ask button and hint — a "black board" that no code change or revert fixed, because it lives in browser storage rather than git. A `ForceLightBoard` component now watches the resolved mode (`editor.user.getIsDarkMode()`, which covers an explicit `dark` preference, a `system` preference resolved from the OS, and tldraw's cross-tab broadcast) and writes `colorScheme: "light"` back whenever it goes dark. A one-shot pin on mount was not enough: Firefox resolves a `system` scheme against the OS setting where Chrome often does not, and a late media-query or broadcast can flip the board after mount. No part of the custom chrome has dark styling, so nothing is lost.
- **Resize (§4):** native tldraw resize is enabled and clamped in `onResize` to 280–720px wide and 160px tall. `AiBlobProps.userSized` stops the ResizeObserver auto-height once the user resizes; `userHeight` remembers that height so collapsing and expanding a hand-sized card returns to the chosen size, while the header's **Reset size** button clears the flag and returns to the default 400px auto-growing card. Shape `w`/`h` are native props, so size survives a refresh, and arrows stay bound to the card edge.

## Addendum 3 (session D)

- **Branch base:** the repo has both `main` (checked out, newest commits including BYOK and self-hosted tldraw assets) and `master` (older). The spec says the default is `master`, but branching from `master` would have discarded the live code, so `session/d-launch-hardening` was cut from `main`. Neither default branch was committed to or merged.
- **Hosted vs BYOK limits:** D1 applies to `POST /api/ask`. When a visitor pastes their own key, `lib/stream.ts` calls the provider straight from the browser and neither rate limits nor the global cap can apply — the visitor is spending their own budget. This is intentional, not a bypass: removing the key restores the hosted, limited path.
- **Rate-limit order:** client-daily → IP-per-minute → IP-daily → global cap. The global counter increments only after the narrow checks pass, so rejected spam does not consume the shared budget. The global key is `huh:ask:global:<UTC day>` with a two-day expiry.
- **Redis fallback:** Upstash is used only when both REST env vars exist. Otherwise a per-process fixed-window map is used, with one `console.warn` per process. Upstash network failures also fall back to memory rather than blocking all asks; the provider spend cap remains the hard backstop.
- **Payload limits:** 6.5 MB raw body (rejected before JSON parsing), then 4 MB decoded image, PNG/JPEG only, question ≤ 1000, board summary ≤ 3000, ancestor context ≤ 4000, history ≤ 20 messages and 12,000 chars. Wrong shape → 400, oversized → 413. Client downscaling to 1600px is convenience; the server enforces regardless.
- **`max_tokens`:** re-introduced at 400 in `lib/llm.ts` (addendum-3 supersedes addendum-2's removal). Every provider request uses it; nothing from the client is trusted. This can truncate long explanations — the spec prioritises cost protection, and the prompt already asks for short gap-first answers. If the owner later wants longer answers, change the constant, not the request body.
- **Anonymous id:** `huh_cid` is a random UUID in an httpOnly, SameSite=Lax cookie with a one-year max age (`Secure` in production). It is set by the ask/feedback routes on first use, never by the page. Only a SHA-256 prefix is logged.
- **Logging:** `/api/ask` logs `{ ts, route, cidHash, status, ms, code? }` as one JSON line. No image, question, prompt, answer or key. Provider error text is truncated when logged.
- **Cookie on errors:** every `/api/ask` failure carries the `Set-Cookie` header too, so a first request that is rejected still leaves the client with an id for the next one.
- **Error mapping (D2):** the client maps `rate_limited`, `daily_cap`, `provider_error`, `too_large`, `bad_request`, `timeout` to fixed human copy, plus client-only `offline`, `empty` and `cut_off`. `too_large`/`bad_request` use the selection-size message from the D2 table; a malformed question is unlikely from this UI. Partial answers survive a mid-stream failure and show a muted `(cut off)` line.
- **Abort paths:** delete (through `lib/lifecycle.ts`), composing-cancel, a superseding send, and the 30s first-token timer all abort. The UI still disables Send while a reply streams (addendum-2 guard), so a “new send” normally cannot happen; `sendQuestion` nevertheless aborts an active stream first so a programmatic call cannot fork two writers. Cleanup is controller-identity checked, so an old stream cannot delete the new stream's registry entry.
- **Retry:** the in-memory payload is reused when present; after a refresh it is rebuilt from the last user message and `buildContext`. The trailing assistant placeholder/partial is popped, the user bubble is never duplicated. `Retry` is available for every error state.
- **Error boundary:** lives outside `<Board>` in `BoardLoader`, so it also catches tldraw mount failures. Snapshot download calls `window.getHuhSnapshot`, which `Board` installs on mount; if the editor itself is gone it downloads a small JSON explaining that the snapshot was unavailable.
- **Onboarding sample:** `editor.putExternalContent({ type: "svg-text", text })` uses tldraw's default SVG handler, so the sample becomes a normal image shape with a real asset (not a custom embed). `huh.onboarded` is written on dismiss, on “Try a sample”, and on the first successful streamed answer; the card also hides on the `huh:onboarded` window event.
- **Help popover:** rendered inside the board's overlay layer with `pointer-events-auto`; it never autofocuses, so blob inputs keep focus. Esc closes it, and a capture-phase pointerdown listener closes it when clicking elsewhere.
- **Feedback storage:** `POST /api/feedback` stores `{ id, messageId, rating, reason, comment, answer, question, promptVersion, model, ts }` — no image, no IP, no raw client id. The Upstash list is trimmed to 5,000 entries; `GET` returns the newest 200 and is 401 unless `ADMIN_TOKEN` is set and matches. Local fallback is one JSON line in the server log.
- **Feedback identity:** `messageId` is `${blobShapeId}:${messageIndex}`. It is stable for a stored thread, but popping a failed assistant message can shift indices; this is acceptable for a prompt-improvement pipeline, not an audit log.
- **Analytics:** PostHog is loaded with a dynamic import only when `NEXT_PUBLIC_POSTHOG_KEY` exists and DNT is off. Autocapture, pageviews, pageleaves, session recording and surveys are disabled; `person_profiles: "identified_only"`. Events contain only names and small enums/booleans. The SDK `ip: false` option is deprecated and has no effect, so the owner must enable **Discard client IP data** in the PostHog project — this is in the README checklist. `lib/analytics.ts` also short-circuits on DNT itself.
- **No user content in analytics:** reviewed every `track()` call; the only props are `source`, `via`, `chip` (chip label, not the question), `isChild`, `collapsed`, `open`, `rating`, `reason` and `code`.
- **Legal pages:** `/privacy` and `/terms` are plain static pages marked **DRAFT — owner must review**. They describe the BYOK path, the anonymous cookie, analytics, feedback and the local-only board. The privacy page notes the owner is in Indonesia and needs a UU PDP review.
- **Open legal questions for the owner:** lawful basis/consent for sending selection images to the AI provider; retention for feedback and rate-limit counters; processor terms / cross-border transfer for the AI provider, Vercel, Upstash and PostHog; a real contact and data-subject request process; whether feedback becomes personal data once a comment is added; age/minor rules for classmates; cookie classification for `huh_cid`; and the correct jurisdiction/liability wording in the terms. The agent is not a lawyer.
- **tldraw license:** the key is wired to `<Tldraw licenseKey={...}>` and empty is a no-op. **The owner must check tldraw's license terms/pricing for this use before any public launch.** The agent did not buy or sign up for anything.
- **Sentry:** skipped this session per the spec's optional cut. `SENTRY_DSN` / `NEXT_PUBLIC_SENTRY_DSN` are reserved in `.env.example`; no SDK is installed, so there is no accidental data collection.
- **Deploy:** both API routes are explicitly on the Node runtime (`maxDuration` 60 for ask, 15 for feedback). `next.config.mjs` adds `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` and a `frame-ancestors 'none'` CSP; root metadata is `noindex, nofollow`.
- **Turbopack cache:** a dev-server crash (`0xc0000142` while spawning the PostCSS child) left a corrupt `.next`; deleting `.next` and restarting fixed it. No code change was needed, and `npm run build` is clean.
- **Not built:** accounts, cloud save, board list, PDF import, payments, multiplayer, new AI features, a feedback admin UI, and Sentry.

## Addendum 4 (Session E)

- **Stop (E1):** the Send button becomes **Stop** while `status === "streaming"`. `lib/stream.ts` keeps a `stopRequests` signal so the abort is distinguished from delete/supersede: the partial text is flushed, `status` returns to `idle`, and the stopped assistant index is stored in the new `AiBlobProps.stopped` prop. The `(stopped)` marker is rendered from that prop only, never written into message content, so it cannot reach history or export. Stopping before the first token removes the empty assistant placeholder. The textarea is `readOnly` rather than `disabled` while streaming so `Esc` can reach it; the effect that focused it after Stop returns focus and puts the caret at the end.
- **Regenerate (E2):** only the last assistant message offers it. It drops that message, keeps the user bubble, and streams a replacement with the same cached `regionImage`, context and question. The server and BYOK paths both use `temperature: 0.45` when the payload carries `regenerate: true` (normal asks stay at 0.3); the flag is validated as a boolean, never a client-supplied temperature. Replacing the message clears its feedback and its `moreOpen` entry.
- **Copy (E2):** two muted actions. “Copy text” strips markdown emphasis/headings while keeping `$...$` LaTeX and always appends the collapsed More section; “Copy LaTeX/Markdown” returns the raw model output minus the `---MORE---` line. Both use `navigator.clipboard.writeText` with a `document.execCommand('copy')` fallback, and show “Copied” for ~1.2s.
- **Edit (E3):** only the last user message, and only when it was typed (no chip `label`, not hidden). Sending replaces from that index onward and streams a fresh answer with the same crop; earlier messages and their More state stay. `Esc`/Cancel clears edit mode. While streaming the pencil is hidden.
- **Autosave (E4):** driven by `editor.store.listen(..., { scope: "document", source: "user" })`, so camera/instance changes never flash the indicator. tldraw owns persistence and exposes no completion hook, so “Saved” is approximated 500ms after the last document change; a localStorage probe catches quota/blocked storage and drives the failure state. The probe is an approximation of IndexedDB health, logged here as required by the spec.
- **Dark mode (E5):** preference (`system` default) is stored in `huh.theme`; `lib/themeBoot.ts` applies the `dark` class before first paint in `layout.tsx`, and `ThemeSync` mirrors the preference to tldraw's `colorScheme`. Tailwind uses a class-based `@custom-variant dark`; blob CSS moved to `.dark .ai-*` overrides, and KaTeX inherits the blob colour. Region capture passes `darkMode: false` (verified against the installed tldraw export options) so the model always receives a light-background PNG. The thread palette is unchanged and remains distinguishable in both themes.
- **Bug report (E6):** `NEXT_PUBLIC_BUG_FORM_URL` wins and is opened as-is; otherwise a prefilled `mailto:` to `NEXT_PUBLIC_CONTACT_EMAIL` contains only the template, app version, user-agent, last error code and timestamp. With neither configured the link renders nothing. `lib/lastError.ts` stores only the error code set by D2 failures.
- **Server output cap:** the uncommitted Session D removal of `MAX_OUTPUT_TOKENS` was reverted to the addendum-3 D1 requirement: 400 tokens, enforced in `lib/llm.ts` for all three providers. Prompt-level length budgets remain removed (addendum-2 3.5), so this is a cost ceiling, not a style limit.
- **Provider verification:** the local `.env.local` has no `LLM_API_KEY`, and this machine could not reach the provider (`fetch failed`), so real streaming could not be exercised end-to-end. All Session E thread behaviour (Stop, Regenerate, Copy, Edit, Retry, feedback) was verified in the browser with a mocked `/api/ask` stream; the owner must re-check one live answer after setting the key.
