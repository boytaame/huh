# Decisions & assumptions

- **Scaffold:** created Next.js manually instead of `create-next-app` because the workspace was not empty (`spec.md`). Pinned TypeScript 5.9 rather than the brand-new TS 7 for ecosystem safety.
- **First question:** originally §5.2's instant path (auto-sent default question). Addendum P3 replaces it: the thread opens in a composing state with chips and a focused input, and the default question is only sent if the user submits an empty input (stored with `hidden: true`). See the addendum section below.
- **Persistence:** uses tldraw's `persistenceKey="ai-canvas-v1"` as instructed. In tldraw 5 this persists to browser-local IndexedDB under that key (older versions used localStorage). It is still purely local, with no database/auth.
- **Instant anchoring:** the region, thread and arrow are created before the PNG capture and network call. The blob shows "Looking at your selection…" while the crop is encoded, then streams. This keeps selection → blob feeling immediate.
- **Image capture:** `editor.toImage(shapesInSelection, { bounds, format: 'png', background: true, padding: 0, pixelRatio: 2 })`, then downscaled client-side to at most 1600px on the long side. The yellow selection shape and arrows are excluded from the capture. A visible background is kept so dark text is legible to the vision model.
- **Crop reuse:** the PNG is cached on both the `ask-region` (`imageDataUrl`) and the `ai-blob` (`regionImage`), as specified, and re-sent on every follow-up.
- **HTML shapes in captures:** tldraw's raster export skips HTML custom shapes. `AiBlobShapeUtil.toSvg` therefore renders a plain-text approximation (last few messages) so a child selection over an AI answer still contains text. The real parent thread messages are also sent in `ancestorContext`, so the model is not relying on the approximation alone.
- **Context budget:** `buildContext` uses a character budget (default 12,000 chars ≈ 3k tokens) rather than counting tokens. Board summary is capped at 2,000 chars, ancestor context at 3,000, and thread history is trimmed oldest-first. Full board JSON is never sent.
- **Ancestor chain:** walks up to 3 levels via `parentId`. AI parents contribute their last 3 messages; text materials contribute up to 1,200 chars; image materials are described by type/size. Regions terminate the walk.
- **Parent detection:** the Ask tool picks the topmost non-arrow/non-region shape whose bounds overlap at least 40% of the drawn selection. This lets a blob be a parent (child threads) without picking up previous yellow overlays.
- **Placement:** tries right of the selection (80px gap), then below-right, below, left. Chooses the first collision-free candidate that is mostly visible in the viewport, falling back to the least-bad candidate. Arrow endpoints are bound to the region's right edge and the blob's left edge with `isPrecise: true`.
- **Streaming ownership:** streaming lives in `lib/stream.ts`, not in the React component, so panning/culling a shape does not abort the request. Store updates are throttled to ~55ms, and a stream is abandoned if its blob is deleted.
- **Retry:** the last request payload is retained per blob. Retry drops the failed assistant placeholder and re-sends the same payload, so history is not duplicated.
- **Export scope:** nodes include `image`, `text`, `ask-region` and `ai-blob` shapes only, matching the schema in §5.5. Other tldraw shapes (geo, draw, note, frames) are not exported. Edges come from native arrow bindings (start → end); parent links live in each node's `parentId`.
- **`getBoardContext()`** returns the board JSON and is exposed on `window` for debugging; prompts use the much smaller `buildContext` output instead.
- **UI chrome:** tldraw's default main menu and page menu are hidden (single-page board, no accounts). The title and Ask controls are custom overlays; exports live in tldraw's native top-right `SharePanel` slot so they never collide with the style panel.
- **Provider defaults:** Gemini 2.5 Flash, Claude Haiku 4.5, GPT-4o mini. All are overridable via `LLM_MODEL`; provider code is confined to `lib/llm.ts`.
- **No extra features:** no auth, DB, sync, OCR, PDF import, study modes, mobile tuning or billing, per §6.

## Addendum 1 (P1–P6)

- **P1 · input isolation:** done with React handlers on the blob's own DOM (`onPointerDown`, `onKeyDown`, `onContextMenu`, `onPaste`) plus native `wheel` listeners on the body and footer. React's synthetic events are not enough for the wheel: tldraw binds `wheel` natively on the canvas element, so a synthetic `stopPropagation` arrives after the camera already moved. The body's `user-select: text` is applied as an inline style (tldraw's cascade otherwise wins) so answer text can be selected and copied while the header keeps `cursor: grab` for dragging.
- **P1 · header drag:** the header deliberately does *not* stop pointer events, so tldraw's own move handles the drag; every other region of the card stops them. Wheel over the body scrolls the answer and only bubbles to the canvas at the scroll limit with Ctrl/Meta held (pinch-zoom escape hatch).
- **P2 · gap-first prompt:** the system prompt in `lib/llm.ts` asks for the specific missing step first (never a generic summary) and separates a short visible answer from optional detail with the `---MORE---` marker. `lib/answer.ts` splits on the marker: everything after it is the collapsed detail behind `More ▾` (`moreOpen`), and only the first line of the visible answer is shown when the thread is collapsed.
- **P2 · default question bubble:** the auto-sent first question is stored as a user message with `hidden: true`, so it never renders as an "Explain this part…" bubble; it still travels in history/export. Typing over it is unnecessary — the thread starts composing instead (P3).
- **P3 · composing state:** dragging a selection no longer calls the LLM. The blob is created with `status: "composing"`, five quick chips from `lib/chips.ts`, an autofocused textarea and no messages. Enter (or a chip) submits; Shift+Enter inserts a newline; Esc cancels. Submitting an empty input sends `DEFAULT_QUESTION` with `hidden: true`.
- **P3 · cancel semantics:** cancelling deletes the thread exactly like the trash button (region → arrow → blob cascade), with no confirmation dialog. It calls `editor.markHistoryStoppingPoint` first: the creation and the cancel often share one pending history diff, and without a stopping point the two diffs cancel out and `Ctrl+Z` cannot restore the thread. Verified: Esc → all three shapes gone → one undo restores region, arrow and blob in `composing`.
- **P4 · anchored regions:** `AskRegionProps` gained `anchorId` and `rel` (anchor-relative bounds). `lib/anchoring.ts` syncs regions whenever the anchor material moves/resizes, including manual region resizes (so `canResize` is on for regions), and skips the update when the region already matches its anchor-relative target — an `applying` flag alone was not reliable because tldraw store side effects can fire after the caller's guard clears.
- **P4 · blob offset:** `AiBlobProps.offsetFromRegion` stores the blob position relative to its region, so a manually dragged blob keeps that offset when the selection moves. `lib/placement.ts` still picks collision-free, viewport-clamped spots for new threads.
- **P4 · migrations:** both custom shape utils ship a versioned migration (`com.tldraw.shape.ask-region/1`, `com.tldraw.shape.ai-blob/1`) — tldraw rejects migration ids that do not use that prefix.
- **P5 · delete cascade:** `lib/lifecycle.ts` handles the three rules with no dialogs: blob → region + arrow, region → arrow (the blob survives as `detached` with a thumbnail of its selection), arrow → the blob is unlinked and detached. Child blobs survive as detached threads (`parentId` cleared). Each cascade is one undo step.
- **P5 · arrow `meta` link:** the region↔blob link lives in the arrow's `meta.thread` instead of only in bindings because tldraw removes arrow bindings *before* a shape's `beforeDelete` runs — binding lookups during the handler returned nothing.
- **P6 · polish:** blob width is fixed at 400px (spec range 380–420) with ≥14px body text; the header (title, collapse, trash) stays visible when collapsed, and collapsing leaves the header plus the first line of the answer. Thread accents come from a five-colour palette (`lib/threads.ts`) chosen per drag, and a detached blob keeps its colour (`AiBlobProps.color` — an extra prop beyond the spec's summary).
- **Not built:** the optional "Auto-explain on select" setting. The addendum marks it optional and the composing flow already gives explicit control.

## Addendum 2 (sessions A and C)

- **Wheel ownership (3.1):** the card attaches one native, non-passive `wheel` listener at its root. Ctrl/Cmd+wheel is preventDefault-ed so the browser page never zooms, then the board zooms around the pointer (`editor.zoomIn/zoomOut` with a viewport-space `Vec`) — superseding addendum-1's "let pinch through" note. Plain wheel only stops propagation, so the answer scrolls and the board neither pans nor zooms.
- **Send guards (3.2):** the send button is disabled when `draft.trim()` is empty or the blob is streaming, and `submit()` bails out early while streaming. Empty Enter is deliberately asymmetric: it sends the default question only while composing (no messages yet), and does nothing on a follow-up thread.
- **Selectable text (3.3):** verified no regression from addendum-1; the body keeps inline `user-select: text` / `cursor: text` and stops pointer events, so a drag selects text instead of moving the card. Only the header drags.
- **Prompt voice (3.5):** added the "stop after the last explanatory step" rule, and the per-chip instruction suffixes now live in `lib/chips.ts` (analogy, reason-only, one worked example with real numbers, verdict-first).
- **No length caps:** the 400-token cap and the "max ~80 words" prompt rule from addendum-2 are gone — they cut explanations off mid-step. Gemini and OpenAI are now called with no output-token limit at all; Anthropic keeps `max_tokens: 8192` only because its API requires the field, set far above any real answer. Length is now guided purely by the content rules (gap first, short steps), not by a budget.
- **Resize (§4):** native tldraw resize is enabled and clamped in `onResize` to 280–720px wide and 160px tall. `AiBlobProps.userSized` stops the ResizeObserver auto-height once the user resizes; `userHeight` remembers that height so collapsing and expanding a hand-sized card returns to the chosen size, while the header's **Reset size** button clears the flag and returns to the default 400px auto-growing card. Shape `w`/`h` are native props, so size survives a refresh, and arrows stay bound to the card edge.
